# AI Components

NoorUI includes 12 components purpose-built for LLM-powered interfaces with full bidirectional support. These cover the entire spectrum of AI interaction patterns: chat, streaming, configuration, and workflow orchestration.

---

## Overview

| Category | Components | Purpose |
|---|---|---|
| **Core** | ChatMessage, StreamingText, PromptInput, ThinkingIndicator | The fundamental building blocks of a chat interface |
| **Advanced** | MessageActions, ModelSelector, ParameterSlider, TokenCounter, ConversationHistory | Controls for power users and configuration surfaces |
| **Workflow** | WorkflowCanvas, WorkflowNode, WorkflowNodes | Visual node-based workflow editors for AI pipelines |

All 12 components are bilingual (English and Arabic), theme-aware, and designed to work correctly in both LTR and RTL layouts.

---

## Core Components

### ChatMessage

Renders a single message in a conversation thread. Supports user, assistant, and system roles with role-aware styling.

<CodeBlock
  filename="ChatMessage usage"
  language="tsx"
  code={`import { ChatMessage } from 'noorui-rtl';

<ChatMessage
  role="user"
  content="How do I implement authentication?"
/>

<ChatMessage
  role="assistant"
  content="Here's a step-by-step guide to implementing JWT authentication..."
  isStreaming
/>

<ChatMessage
  role="system"
  content="You are a helpful coding assistant."
/>`}
/>

**RTL behavior:** User bubbles align to the inline-end (right in LTR, left in RTL). Assistant bubbles align to the inline-start. This mirrors the natural reading direction -- your own messages appear on "your side" of the conversation regardless of language direction.

### StreamingText

Renders text with a typewriter animation, simulating LLM token-by-token output.

<CodeBlock
  filename="StreamingText usage"
  language="tsx"
  code={`import { StreamingText } from 'noorui-rtl';

<StreamingText
  text="The quick brown fox jumps over the lazy dog."
  speed={30}
  showCursor
/>

// With pause/resume control
<StreamingText
  text={longResponse}
  speed={20}
  showCursor
  onComplete={() => console.log('Streaming finished')}
/>`}
/>

**Key features:** Configurable character-per-millisecond speed, animated cursor with blinking effect, pause and resume capability, and a completion callback. The cursor renders at the inline-end of the text in both LTR and RTL.

### PromptInput

An auto-resizing textarea with send functionality, designed as the primary input for chat interfaces.

<CodeBlock
  filename="PromptInput usage"
  language="tsx"
  code={`import { PromptInput } from 'noorui-rtl';

<PromptInput
  placeholder="Ask anything..."
  onSend={(message) => handleSend(message)}
  isLoading={isGenerating}
/>`}
/>

**Key features:** Auto-resizes vertically as the user types, Enter sends the message, Shift+Enter inserts a newline, send button shows a loading spinner during generation, and placeholder text comes from the i18n system.

### ThinkingIndicator

Animated indicator shown while the LLM is processing a request.

<CodeBlock
  filename="ThinkingIndicator usage"
  language="tsx"
  code={`import { ThinkingIndicator } from 'noorui-rtl';

<ThinkingIndicator variant="dots" />
<ThinkingIndicator variant="pulse" />
<ThinkingIndicator variant="wave" />
<ThinkingIndicator variant="typing" message="Analyzing your code..." />`}
/>

**Key features:** Four animation variants (dots, pulse, wave, typing), optional custom message, bilingual default messages ("Thinking..." / "جاري التفكير..."), and smooth enter/exit transitions.

## Advanced Components

### MessageActions

A toolbar of actions that appears on hover or focus of a chat message.

<CodeBlock
  filename="MessageActions usage"
  language="tsx"
  code={`import { MessageActions } from 'noorui-rtl';

<MessageActions
  onCopy={() => copyToClipboard(message)}
  onRegenerate={() => regenerateResponse(messageId)}
  onEdit={() => setEditing(messageId)}
  onThumbsUp={() => rate(messageId, 'up')}
  onThumbsDown={() => rate(messageId, 'down')}
/>`}
/>

**RTL behavior:** The action toolbar positions itself at the inline-end of the message bubble. Icon order mirrors naturally through flexbox logical properties.

### ModelSelector

A dropdown for selecting between available LLM models, with model specification cards.

<CodeBlock
  filename="ModelSelector usage"

**Key features:** Model cards showing speed, context window length, and capability descriptions. All descriptions have Arabic translations in the i18n system.

### TokenCounter

A progress bar showing token usage against the model's context window limit.

<CodeBlock
  filename="TokenCounter usage"
  language="tsx"
  code={`import { TokenCounter } from 'noorui-rtl';

<TokenCounter
  used={45200}
  limit={128000}
/>
// Renders: 45,200 / 128,000 with a green progress bar

// In Arabic RTL mode:

**Key features:** Color-coded progress bar that shifts from green (safe) to yellow (warning at 75%) to red (danger at 90%). Numeral formatting adapts to locale -- Western digits in LTR, Arabic-Indic digits in RTL.

<CodeBlock

## Workflow Components

### WorkflowCanvas

A drag-and-drop canvas for building visual AI pipelines. Nodes represent operations (LLM calls, conditions, data transforms) and edges represent data flow between them.

<CodeBlock
  filename="WorkflowCanvas usage"
  language="tsx"
  code={`import { WorkflowCanvas, WorkflowNode, LLMNode, ConditionNode, DataNode, OutputNode } from 'noorui-rtl';

<WorkflowCanvas
  nodes={workflowNodes}
  edges={workflowEdges}
  onNodeAdd={handleAddNode}
  onEdgeConnect={handleConnect}
  onNodeMove={handleMove}
>
  <LLMNode id="llm-1" model="gpt-4" prompt="Summarize the input" />
  <ConditionNode id="cond-1" condition="sentiment > 0.5" />
  <DataNode id="data-1" source="api" />
  <OutputNode id="out-1" format="json" />
</WorkflowCanvas>`}
/>

### WorkflowNode

The base node component with input and output connection ports.

### WorkflowNodes

Pre-built node types for common AI workflow operations:
- **LLMNode** -- Configures an LLM call with model, prompt template, and parameters
- **ConditionNode** -- Branching logic based on output conditions
- **DataNode** -- Input data from APIs, databases, or file uploads
- **OutputNode** -- Final output formatting (JSON, text, structured data)

## RTL Considerations for AI Interfaces

AI chat interfaces present unique bidirectional challenges that generic components do not face.

<CodeBlock
  filename="RTL-specific behaviors in AI components"
  language="text"
  code={`Chat bubbles
  LTR: user messages on the right, assistant on the left
  RTL: user messages on the left, assistant on the right
  Implementation: flexbox with justify-end/justify-start + logical properties

Streaming text
  LTR: cursor appears at the right edge of text
  RTL: cursor appears at the left edge of text
  Implementation: inline-end positioning with CSS logical properties

Code blocks within messages
  Always LTR regardless of document direction
  Implementation: dir="ltr" on <pre> and <code> elements
  Arabic comments within code remain readable

Token counts
  LTR: "45,200 / 128,000"
  RTL: "٤٥٬٢٠٠ / ١٢٨٬٠٠٠"
  Implementation: ArabicNumber component for locale-aware formatting

Action toolbars
  LTR: actions appear at the right edge of messages
  RTL: actions appear at the left edge of messages
  Implementation: absolute positioning with inset-inline-end`}
/>

<DesignDecision title="Code blocks stay LTR, always">
  <p>
    Programming languages are written left-to-right regardless of the user's language. When an assistant message contains a code block in an RTL interface, the code block renders in LTR with <code>dir="ltr"</code>. The surrounding message text remains RTL. This mixed-direction rendering is handled automatically -- components detect code fences in markdown content and apply the correct direction attribute.
  </p>
</DesignDecision>

## Bilingual AI

Every label, placeholder, status message, and description in the AI component suite is sourced from the i18n system. This includes:

- **Prompt placeholders:** "Ask anything..." / "...اسأل أي شيء"
- **Thinking messages:** "Thinking..." / "جاري التفكير..."
- **Action labels:** "Copy", "Regenerate", "Edit" / "نسخ", "إعادة التوليد", "تعديل"
- **Model descriptions:** Full Arabic translations for model capability descriptions
- **Parameter labels:** "Temperature", "Max Tokens", "Top P" with Arabic equivalents
- **Date groupings:** "Today", "Yesterday", "Last 7 days" with Arabic equivalents
- **Error states:** "Failed to generate response" / "فشل في توليد الاستجابة"

No hardcoded English strings exist in any AI component. The `content[locale]` pattern is used consistently throughout.

<DesignDecision title="RTL is not an afterthought in AI interfaces" type="tip">
  <p>
    Most AI chat interfaces are designed exclusively for English. NoorUI's AI components were built bidirectional from the start. This means an Arabic-speaking user gets the same quality experience as an English-speaking user: proper bubble alignment, correct numeral formatting, culturally appropriate date grouping, and natural reading flow. The AI components are not LTR components with an RTL patch. They are direction-agnostic components that work correctly in both layouts by design.
  </p>
</DesignDecision>
