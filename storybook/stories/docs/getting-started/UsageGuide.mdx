# Usage Guide

This guide covers how to use NoorUI components effectively, from imports and utilities to provider configuration and building complete layouts that work in both LTR and RTL.

---

## Import Patterns

NoorUI components are imported from the `components/ui` directory using path aliases:

<CodeBlock
  language="tsx"
  filename="Importing components"
  code={`// Individual components
import { Button, Card, CardHeader, CardTitle, CardContent, Input, Badge } from 'noorui-rtl';

// Providers
import { DirectionProvider, useDirection } from 'noorui-rtl';

// Utilities
import { cn, applyTheme } from 'noorui-rtl';`}
/>

Each component file exports the component itself along with any related subcomponents (e.g., `Card` exports `CardHeader`, `CardTitle`, `CardContent`, `CardFooter`, and `CardDescription`).

## The `cn()` Utility

The `cn()` function is NoorUI's class merging utility. It combines `clsx` (for conditional classes) with `tailwind-merge` (for resolving Tailwind class conflicts).

<CodeBlock
  language="tsx"
  filename="lib/utils.ts"
  code={`import { type ClassValue, clsx } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}`}
/>

Use `cn()` whenever you combine or override Tailwind classes:

<CodeBlock
  language="tsx"
  filename="Usage examples"
  code={`// Merge component defaults with custom classes
<div className={cn('rounded-lg border bg-card p-6', className)}>

// Conditional classes
<span className={cn(
  'text-sm font-medium',
  isActive && 'text-primary',
  isDisabled && 'opacity-50 cursor-not-allowed'
)}>

// Override defaults safely (tailwind-merge resolves conflicts)
<Button className={cn('px-8 py-4')} />
// If Button has default px-4, tailwind-merge keeps only px-8`}
/>

<DesignDecision title="Why cn() instead of plain template literals?" type="decision">
  <p>Template literals like `\`text-sm \${isActive ? 'text-primary' : ''}\`` do not resolve conflicting Tailwind classes. If a component has `px-4` internally and you pass `px-8`, both classes remain and the result is unpredictable. The `cn()` utility ensures the last class wins.</p>
</DesignDecision>

## Provider Hierarchy

NoorUI uses a layered provider architecture. Understanding the purpose of each layer helps you configure your app correctly and use the right hooks.

### DirectionProvider

Manages the document direction (`ltr` or `rtl`) and locale (`en` or `ar`). Wraps all other providers.

<CodeBlock
  language="tsx"
  filename="Provider setup"
  code={`import { DirectionProvider } from 'noorui-rtl';

// In your layout:
<DirectionProvider>
  {/* All child components can use useDirection() */}
</DirectionProvider>`}
/>

The `useDirection()` hook provides:

<CodeBlock
  language="tsx"
  filename="useDirection() return type"
  code={`const {
  direction,     // 'ltr' | 'rtl' — current document direction
  setDirection,  // (dir: 'ltr' | 'rtl') => void — updates dir, lang, and localStorage
  locale,        // 'en' | 'ar' — current locale
  setLocale,     // (locale: 'en' | 'ar') => void — updates locale and direction together
} = useDirection();`}
/>

### ThemeProvider (next-themes)

Handles light and dark mode. Uses the `class` strategy to toggle a `.dark` class on `<html>`.

<CodeBlock
  language="tsx"
  filename="Theme provider configuration"
  code={`import { ThemeProvider } from 'next-themes';

<ThemeProvider
  attribute="class"
  defaultTheme="system"
  enableSystem
  disableTransitionOnChange={false}
>
  {children}
</ThemeProvider>`}
/>

### IconContext.Provider (@phosphor-icons/react)

Sets default properties for all Phosphor icons in the tree.

<CodeBlock
  language="tsx"
  filename="Icon context"
  code={`import { IconContext } from '@phosphor-icons/react';

<IconContext.Provider value={{ weight: 'duotone', color: 'currentColor' }}>
  {children}
</IconContext.Provider>`}
/>

With this provider in place, every Phosphor icon you use inherits `duotone` weight and `currentColor`, so icons automatically match the surrounding text color.

<DesignDecision title="Provider ordering matters" type="warning">
  <p>DirectionProvider must be the outermost provider because ThemeProvider and IconContext may need direction context. The correct nesting is: DirectionProvider &gt; ThemeProvider &gt; IconContext.Provider.</p>
</DesignDecision>

## Theme Switching with `applyTheme()`

NoorUI ships with four design themes -- **Minimal**, **Futuristic**, **Cozy**, and **Artistic** -- each defined as a CSS class that overrides design token custom properties.

<CodeBlock
  language="tsx"
  filename="Applying a theme programmatically"
  code={`import { applyTheme } from 'noorui-rtl';

// Apply a theme — adds CSS class to document root
applyTheme('cozy');     // Adds class "theme-cozy"
applyTheme('minimal');  // Adds class "theme-minimal"
applyTheme('futuristic');
applyTheme('artistic');`}
/>

Behind the scenes, `applyTheme()` removes any existing `theme-*` class from `<html>` and adds the new one. The theme class overrides CSS custom properties like `--primary`, `--radius`, and `--muted`, so all components update instantly without re-rendering.

<CodeBlock
  language="css"
  filename="How theme classes work (simplified)"
  code={`/* Default tokens */
:root {
  --primary: 239 84% 67%;
  --radius: 0.5rem;
}

/* Cozy theme overrides */
.theme-cozy {
  --primary: 25 95% 53%;
  --radius: 1rem;
}`}
/>

## Using the `useDirection()` Hook

The `useDirection()` hook is your primary tool for direction-aware behavior in components.

<CodeBlock
  language="tsx"
  filename="Direction-aware component"
  code={`import { useDirection } from 'noorui-rtl';

function UserGreeting() {
  const { direction, locale, setDirection } = useDirection();

  return (
    <div>
      <p>Current direction: {direction}</p>
      <p>Current locale: {locale}</p>

      <button onClick={() => setDirection(direction === 'ltr' ? 'rtl' : 'ltr')}>
        Toggle Direction
      </button>
    </div>
  );
}`}
/>

### When to use `useDirection()`

- **Layout alignment** -- When you need to conditionally position elements based on direction (e.g., placing a sidebar).
- **Locale-dependent formatting** -- Dates, numbers, and currencies that should format differently for English vs. Arabic.
- **Animation direction** -- Slide-in animations that should come from the correct side.

### When NOT to use `useDirection()`

<DesignDecision title="Direction hook is not for text content" type="warning">
  <p>Do not use `useDirection()` to swap between English and Arabic strings. Use an internationalization (i18n) system like next-intl or react-intl instead. The direction hook is for layout and formatting, not content translation.</p>
</DesignDecision>

<DesignDecision title="Prefer logical CSS properties over direction checks" type="tip">
  <p>Most of the time, you do not need `useDirection()` at all. NoorUI components use CSS logical properties (`margin-inline-start`, `padding-inline-end`, `border-start-start-radius`) that automatically flip in RTL. Only reach for the hook when you need direction in JavaScript logic.</p>
</DesignDecision>

## Complete Page Layout Example

Here is a full example of a contact form Card that works correctly in both LTR and RTL, using several NoorUI components together:

<CodeBlock
  language="tsx"
  filename="app/contact/page.tsx"
  code={`'use client';

import { Card, CardHeader, CardTitle, CardDescription, CardContent, CardFooter, Button, Input, useDirection } from 'noorui-rtl';

export default function ContactPage() {
  const { direction, locale } = useDirection();

  return (
    <main className="flex min-h-screen items-center justify-center p-8 bg-background">
      <Card className="w-full max-w-md">
        <CardHeader>
          <CardTitle>
            {locale === 'ar' ? 'تواصل معنا' : 'Contact Us'}
          </CardTitle>
          <CardDescription>
            {locale === 'ar'
              ? 'سنرد عليك في أقرب وقت ممكن'
              : 'We will get back to you as soon as possible'}
          </CardDescription>
        </CardHeader>

        <CardContent className="flex flex-col gap-4">
          <div className="flex flex-col gap-2">
            <label htmlFor="name" className="text-sm font-medium text-foreground">
              {locale === 'ar' ? 'الاسم' : 'Name'}
            </label>
            <Input
              id="name"
              placeholder={locale === 'ar' ? 'أدخل اسمك' : 'Enter your name'}
            />
          </div>

          <div className="flex flex-col gap-2">
            <label htmlFor="email" className="text-sm font-medium text-foreground">
              {locale === 'ar' ? 'البريد الإلكتروني' : 'Email'}
            </label>
            <Input
              id="email"
              type="email"
              placeholder={locale === 'ar' ? 'أدخل بريدك الإلكتروني' : 'Enter your email'}
            />
          </div>

          <div className="flex flex-col gap-2">
            <label htmlFor="message" className="text-sm font-medium text-foreground">
              {locale === 'ar' ? 'الرسالة' : 'Message'}
            </label>
            <textarea
              id="message"
              rows={4}
              className="flex w-full rounded-md border border-input bg-background px-3 py-2 text-sm ring-offset-background placeholder:text-muted-foreground focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring"
              placeholder={locale === 'ar' ? 'اكتب رسالتك هنا...' : 'Write your message here...'}
            />
          </div>
        </CardContent>

        <CardFooter>
          <Button className="w-full" variant="primary">
            {locale === 'ar' ? 'إرسال' : 'Send Message'}
          </Button>
        </CardFooter>
      </Card>
    </main>
  );
}`}
/>

Notice how the layout code contains no explicit `text-align: right` or directional margins. The `flex`, `gap`, padding, and border utilities all use logical properties under the hood, so the form naturally mirrors when direction switches to RTL.

<DesignDecision title="Let the framework handle direction" type="tip">
  <p>In this example, `useDirection()` is only used for content strings (which would normally come from an i18n system). All visual layout -- spacing, alignment, borders -- adapts automatically through CSS logical properties and Tailwind's built-in RTL support.</p>
</DesignDecision>
