# Icons

NoorUI uses [Phosphor Icons](https://phosphoricons.com) via `@phosphor-icons/react`. Phosphor provides a comprehensive, consistent icon set with multiple weights. NoorUI standardizes on the **duotone** weight for a distinctive two-tone visual style, configured globally through React context.

---

## Setup: IconContext Provider

The icon weight and color are set once at the app root using Phosphor's `IconContext.Provider`. This eliminates the need to pass `weight` and `color` props to every icon instance:

<CodeBlock
  filename="providers/design-system-provider.tsx"
  language="tsx"
  code={`import { IconContext } from '@phosphor-icons/react';

export function DesignSystemProvider({ children }) {
  return (
    <IconContext.Provider value={{ weight: 'duotone', color: 'currentColor' }}>
      {children}
    </IconContext.Provider>
  );
}`}
/>

Key configuration:
- **`weight: 'duotone'`** -- All icons render with a two-tone style where the secondary shape has reduced opacity. This gives icons depth and visual interest.
- **`color: 'currentColor'`** -- Icons inherit their color from the parent element's `color` property, making them work seamlessly with Tailwind text utilities like `text-primary`, `text-muted-foreground`, etc.

## The Critical Rule: Never Use Directional Icons for Navigation

<DesignDecision title="Use ButtonArrow, Not Raw Arrow Icons" type="warning">
  <p>
    <strong>Never</strong> use <code>ArrowRight</code>, <code>ArrowLeft</code>, <code>CaretRight</code>, or <code>CaretLeft</code> directly in navigation buttons. A right-pointing arrow means "forward" in LTR but "backward" in RTL. If you use a raw icon, it will point the wrong way for half your users.
  </p>
  <p>
    Instead, use the <code>ButtonArrow</code> component, which accepts a semantic <code>direction</code> prop (<code>'forward'</code>, <code>'back'</code>, <code>'external'</code>) and handles RTL mirroring automatically using <code>rtl:rotate-180</code>.
  </p>
</DesignDecision>

## The ButtonArrow Component

`ButtonArrow` wraps the standard `Button` with directional icon logic. It selects the correct icon based on semantic direction and applies RTL mirroring via Tailwind:

<CodeBlock
  filename="components/ui/button-arrow.tsx"
  language="tsx"
  code={`// Semantic directions -- not physical directions
type ArrowDirection = 'forward' | 'back' | 'external';

// Usage examples:

// "Continue" / "Next" -- arrow points forward
<ButtonArrow direction="forward">
  Continue
</ButtonArrow>

// "Go back" -- arrow points backward
<ButtonArrow direction="back">
  Back to Dashboard
</ButtonArrow>

// External link -- diagonal arrow, mirrored in RTL
<ButtonArrow direction="external" asChild>
  <a href="https://docs.noorui.dev" target="_blank" rel="noopener noreferrer">
    View Documentation
  </a>
</ButtonArrow>

// Chevron style instead of arrow
<ButtonArrow direction="forward" icon="chevron">
  Next Step
</ButtonArrow>`}
/>

### How It Works Internally

- **`direction="forward"`**: Renders `CaretRight` (or `ArrowRight`) with `rtl:rotate-180` -- the icon flips to point left in RTL.
- **`direction="back"`**: Renders `CaretLeft` (or `ArrowLeft`) with `rtl:rotate-180` -- the icon flips to point right in RTL.
- **`direction="external"`**: Renders `ArrowUpRight` with `rtl:scale-x-[-1]` -- the diagonal arrow mirrors horizontally.
- **`iconPosition="auto"`**: Forward/external icons appear at the "end" of the button, back icons appear at the "start".

## Manual Icon Mirroring

For cases outside of ButtonArrow -- breadcrumbs, pagination arrows, sidebar chevrons -- you need to manually apply RTL mirroring. The pattern is consistent:

<CodeBlock
  filename="Manual mirroring pattern"
  language="tsx"
  code={`import { CaretRight, CaretLeft } from '@phosphor-icons/react';

{/* Breadcrumb separator */}
<CaretRight className="h-3.5 w-3.5 text-muted-foreground rtl:rotate-180" />

{/* Pagination next arrow */}
<CaretRight className="h-4 w-4 rtl:rotate-180" />

{/* Sidebar expand chevron */}
<CaretRight className="h-4 w-4 transition-transform rtl:rotate-180" />`}
/>

### Rotation vs. Flip

There are two CSS techniques for mirroring icons:

<TokenTable
  title="Mirroring Techniques"
  tokens={[
    { name: 'rtl:rotate-180', value: 'transform: rotate(180deg)', description: 'Rotates the icon 180 degrees. Preferred for arrows and chevrons -- visually identical to a horizontal flip for symmetric shapes.' },
    { name: 'rtl:scale-x-[-1]', value: 'transform: scaleX(-1)', description: 'Horizontally flips the icon. Required for diagonal arrows (like ArrowUpRight) where rotation would change the direction.' },
  ]}
/>

<DesignDecision title="When to Use Rotation vs. Flip">
  <p>
    <strong>Use <code>rtl:rotate-180</code></strong> for horizontal arrows and chevrons (CaretRight, CaretLeft, ArrowRight, ArrowLeft). Rotation is preferred because it works identically to a flip for symmetric horizontal shapes and is more commonly understood.
  </p>
  <p>
    <strong>Use <code>rtl:scale-x-[-1]</code></strong> for diagonal or asymmetric icons (ArrowUpRight, ArrowDownRight). Rotating these 180 degrees would point them in the wrong direction -- flipping horizontally preserves the vertical component while reversing only the horizontal axis. The ButtonArrow component uses this for <code>direction="external"</code>.
  </p>
</DesignDecision>

## Icon Mirroring Reference

Not all icons should mirror in RTL. Physical objects, universal symbols, and non-directional shapes stay the same. Only icons that represent directional flow or navigation should flip.
