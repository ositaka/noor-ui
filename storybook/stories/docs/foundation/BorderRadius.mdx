# Border Radius

Border radius is one of the strongest visual differentiators between NoorUI's themes. A single CSS variable, `--radius`, controls the base radius from which all other radius values are derived. Each theme sets its own `--radius`, giving every component a distinct shape personality -- from razor-sharp (Artistic) to pill-like (Cozy).

---

## The Radius Variable System

The `--radius` variable is defined on `:root` and overridden per theme. Two derived values -- `--radius-md` and `--radius-sm` -- are calculated from the base:

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`@theme {
  --radius-lg: var(--radius);
  --radius-md: calc(var(--radius) - 2px);
  --radius-sm: calc(var(--radius) - 4px);
}

:root {
  --radius: 0.5rem;
}`}
/>

This means changing `--radius` on a theme class cascades through every component in the system. A card, a button, an input, and a badge all shift proportionally.

## The Squircle Enhancement

NoorUI includes a progressive enhancement for browsers that support the `corner-shape` CSS property (Chrome 138+):

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`:root {
  --corner-shape: squircle;
}

@layer base {
  * {
    corner-shape: var(--corner-shape);
  }
}`}
/>

<DesignDecision title="Squircle: Progressive Enhancement, Not a Requirement">
  <p>
    A squircle is a superellipse-based corner shape that produces smoother, more organic rounding than standard circular arcs. Apple uses squircle corners throughout iOS and macOS. The <code>corner-shape: squircle</code> property is a CSS proposal that shipped in Chrome 138. In browsers that support it, NoorUI components get smoother corners automatically. In browsers that do not, standard <code>border-radius</code> applies as a graceful fallback. No feature detection is needed -- the property is simply ignored by unsupported browsers.
  </p>
</DesignDecision>

The squircle enhancement is most noticeable at larger radius values (Cozy and Futuristic themes), where the difference between a circular arc and a superellipse becomes visually apparent.

## Usage Patterns

<CodeBlock
  filename="Border radius usage"
  language="tsx"
  code={`{/* Large surfaces use rounded-lg (the base --radius) */}
<div className="rounded-lg border border-border bg-card p-6">
  Card, Dialog, Sheet
</div>

{/* Interactive elements use rounded-md */}
<button className="rounded-md bg-primary text-primary-foreground px-4 py-2">
  Button
</button>
<input className="rounded-md border border-input px-3 py-2" />

{/* Small inline elements use rounded-sm */}
<span className="rounded-sm bg-muted px-2 py-0.5 text-xs">
  Badge
</span>

{/* Full rounding for avatars and pills */}
<div className="rounded-full w-10 h-10 bg-primary" />
<span className="rounded-full bg-primary/10 text-primary px-3 py-1 text-sm">
  Pill tag
</span>

{/* Directional rounding with logical properties */}
<div className="rounded-s-lg">Rounded on the start side only</div>
<div className="rounded-e-lg">Rounded on the end side only</div>`}
/>

<DesignDecision title="Use Semantic Radius Tokens, Not Hardcoded Values" type="warning">
  <p>
    Avoid hardcoding pixel values like <code>rounded-[8px]</code> or <code>rounded-[12px]</code>. Always use the semantic tokens (<code>rounded-sm</code>, <code>rounded-md</code>, <code>rounded-lg</code>) so that components automatically adapt when the theme changes. Hardcoded values will break theme consistency.
  </p>
</DesignDecision>
