# Typography

NoorUI's type system is designed from the ground up for bilingual interfaces. It handles the fundamental differences between Latin and Arabic scripts through direction-aware font switching, automatic letter-spacing rules, and per-theme typographic tuning -- all driven by CSS custom properties.

---

NoorUI uses four font families, each selected for a specific purpose:

The Artistic theme overrides both `--font-body` and `--font-heading` to Georgia, and switches the RTL font to `'Noto Naskh Arabic', Georgia, serif` for a calligraphic feel.

---

## Direction-Aware Font Switching

Fonts switch automatically based on the `dir` attribute on the document or any parent element. No JavaScript, no conditional logic -- pure CSS:

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`[dir='ltr'] {
  font-family: var(--font-body);
  letter-spacing: var(--body-letter-spacing);
}

[dir='rtl'] {
  font-family: var(--font-rtl);
  letter-spacing: normal;
}

[dir='ltr'] :is(h1, h2, h3, h4, h5, h6) {
  letter-spacing: var(--heading-letter-spacing);
}`}
/>

When the `dir` attribute changes from `ltr` to `rtl`, the entire page switches from Inter to IBM Plex Sans Arabic (or from Georgia to Noto Naskh Arabic in the Artistic theme). This happens at the CSS level with zero JavaScript runtime cost.

## Letter-Spacing: The Critical RTL Rule

<DesignDecision title="Why Letter-Spacing Is Stripped for RTL">
  <p>
    Arabic is a <strong>connected script</strong> -- letters within a word physically join to form ligatures. Adding letter-spacing to Arabic text breaks these connections, making words appear as disconnected fragments. This is the typographic equivalent of placing a space between every letter in English: "H e l l o". It renders the text visually incorrect and harder to read.
  </p>
  <p>
    NoorUI enforces <code>letter-spacing: normal</code> for all RTL content, regardless of what the theme's <code>--body-letter-spacing</code> or <code>--heading-letter-spacing</code> tokens specify. This rule is absolute and cannot be overridden by theme configuration. It is one of the most important bidirectional typography rules in the system.
  </p>
</DesignDecision>

<DirectionComparison>
  <div>
    <h3 style={{ fontSize: '1.5rem', fontWeight: 700, marginBottom: '0.5rem', letterSpacing: '-0.01em' }}>
      Project Dashboard
    </h3>
    <p style={{ fontSize: '0.875rem', lineHeight: 1.6, opacity: 0.7 }}>
      Manage your team's tasks and track progress across all active projects with real-time updates and collaborative tools.
    </p>
  </div>
</DirectionComparison>

Notice how the English text uses subtle negative letter-spacing on the heading for a tighter, modern feel, while the Arabic text uses its natural spacing that preserves connected letterforms.

## Artistic Theme: Serif Typography

The Artistic theme stands apart by using serif fonts instead of sans-serif. This creates an editorial, print-inspired feel:

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`.theme-artistic {
  --font-body: Georgia, 'Times New Roman', serif;
  --font-heading: Georgia, 'Times New Roman', serif;
  --font-rtl: 'Noto Naskh Arabic', Georgia, serif;
  --heading-font-weight: 400;
  --body-line-height: 1.8;
}`}
/>

<DesignDecision title="Monospace Stays Consistent" type="tip">
  <p>
    JetBrains Mono is used for code in both LTR and RTL contexts. Code is always displayed LTR (using the <code>dir="ltr"</code> attribute on code blocks) regardless of the page direction, because programming languages are written left-to-right. The <code>CodeBlock</code> component handles this automatically.
  </p>
</DesignDecision>
