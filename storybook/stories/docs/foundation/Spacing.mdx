# Spacing & Layout

NoorUI uses a consistent spacing scale combined with CSS logical properties to create layouts that adapt automatically between LTR and RTL. This page covers the spacing token system, the logical property conventions, and the container utility.

---

## Logical Properties: The Foundation of Bidirectional Layout

Logical properties are CSS properties that reference the **start** and **end** of content flow rather than physical **left** and **right** directions. In LTR, "start" maps to left and "end" maps to right. In RTL, they flip automatically.

NoorUI uses logical properties exclusively. This is the single most important pattern for making bidirectional layouts work without conditional logic.

<DesignDecision title="Why Logical Properties Make Bidirectional 'Free'">
  <p>
    With physical properties like <code>padding-left</code> and <code>margin-right</code>, you need to write separate RTL overrides for every directional value. This is error-prone, doubles your CSS, and creates maintenance nightmares. Logical properties like <code>padding-inline-start</code> and <code>margin-inline-end</code> automatically flip in RTL -- one declaration, both directions, zero bugs.
  </p>
  <p>
    This is not an optimization or a nice-to-have. It is the architectural decision that makes NoorUI's bidirectional support reliable. Every component, every layout, every spacing value uses logical properties. If you find a physical <code>left</code>/<code>right</code> in the codebase, it is almost certainly a bug.
  </p>
</DesignDecision>

## Logical Properties in Action

Here is a card layout using only logical properties. The icon, text, and badge all reposition correctly in RTL without any code changes:

  <div style={{ display: 'flex', alignItems: 'center', gap: '0.75rem', padding: '1rem', borderRadius: '0.5rem', border: '1px solid var(--colors-border, #e5e7eb)' }}>
    <div style={{ width: '2.5rem', height: '2.5rem', borderRadius: '0.375rem', backgroundColor: 'hsl(var(--primary, 239 84% 67%) / 0.1)', display: 'flex', alignItems: 'center', justifyContent: 'center', flexShrink: 0 }}>
      <span style={{ fontSize: '1.25rem' }}>📊</span>
    </div>
    <div style={{ flex: 1, minWidth: 0 }}>
      <p style={{ fontWeight: 600, fontSize: '0.875rem' }}>Analytics Report</p>
      <p style={{ fontSize: '0.75rem', opacity: 0.6 }}>Updated 2 hours ago</p>
    </div>
    <span style={{ fontSize: '0.75rem', fontWeight: 500, padding: '0.125rem 0.5rem', borderRadius: '9999px', backgroundColor: 'hsl(var(--success, 142 76% 36%) / 0.1)', color: 'hsl(var(--success, 142 76% 36%))' }}>New</span>
  </div>
</DirectionComparison>

The layout above uses `gap` (direction-agnostic) and flexbox (which respects `dir` automatically). The icon stays at the start, the badge stays at the end, and the text fills the middle -- in both directions.

## The Container Utility

NoorUI provides a custom `container` utility that uses logical properties for horizontal centering and responsive padding:

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`@utility container {
  margin-inline: auto;
  padding-inline: 1rem;

  @media (width >= 640px) {
    padding-inline: 2rem;
  }
  @media (width >= 1024px) {
    padding-inline: 4rem;
  }
  @media (width >= 1280px) {
    padding-inline: 5rem;
  }
  @media (width >= 1400px) {
    max-width: 1400px;
    padding-inline: 6rem;
  }
}`}
/>

Key details:
- Uses `margin-inline: auto` instead of `margin-left: auto; margin-right: auto` for consistency
- Uses `padding-inline` instead of `padding-left`/`padding-right` for RTL support
- Progressive padding increase at each breakpoint keeps content comfortably inset
- Maximum width of `1400px` prevents content from stretching too wide on large screens

<DesignDecision title="No Fixed Left/Right Padding" type="tip">
  <p>
    The container uses <code>padding-inline</code> exclusively. This means the same container works perfectly in both LTR and RTL layouts. In RTL, the padding that appears on the "left" side in LTR automatically moves to the "right" side -- because <code>padding-inline</code> refers to the start and end of the inline axis, not physical sides.
  </p>
</DesignDecision>
