# Colors

NoorUI's color system is built on CSS custom properties using raw HSL values. Every color in the palette is a semantic token that adapts automatically across five themes and two color modes (light and dark). Switch the theme and mode from the Storybook toolbar above to see the swatches update in real time.

## How the Color System Works

NoorUI stores colors as **raw HSL values without the `hsl()` wrapper**. This is a deliberate architecture choice that powers the entire theming and opacity system.

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`:root {
  --primary: 239 84% 67%;
  --success: 142 76% 36%;
  --border: 214.3 31.8% 91.4%;
}`}
/>

The `@theme` block in Tailwind CSS v4 then registers these as full color values for utility generation:

<CodeBlock
  filename="styles/globals.css"
  language="css"
  code={`@theme {
  --color-primary: hsl(var(--primary));
  --color-success: hsl(var(--success));
  --color-border: hsl(var(--border));
}`}
/>

<DesignDecision title="Why HSL Without the Wrapper?">
  <p>
    Storing raw HSL values (e.g., <code>239 84% 67%</code> instead of <code>hsl(239 84% 67%)</code>) enables Tailwind's opacity modifier syntax. You can write <code>bg-primary/50</code> to get a 50% opacity primary background, or <code>text-success/80</code> for 80% opacity success text. If the variable already contained the <code>hsl()</code> wrapper, Tailwind could not inject an alpha channel and opacity modifiers would break.
  </p>
  <p>
    This is the same pattern used by shadcn/ui and has become the standard approach for Tailwind CSS theming with CSS custom properties.
  </p>
</DesignDecision>

## Dark Mode Color Shifts

In dark mode, colors are not simply inverted. They are carefully re-tuned for dark backgrounds:

- **Background/foreground** flip: dark near-black backgrounds, light near-white text
- **Primary** retains its hue but foreground shifts from light to dark for contrast
- **Muted** becomes a dark gray instead of a light one
- **Status colors** increase lightness by ~10-15% to maintain vibrancy against dark surfaces
- **Destructive** shifts from a bright red (`0 84.2% 60.2%`) to a deeper, more subdued tone (`0 62.8% 30.6%`) that does not overwhelm dark interfaces

<CodeBlock
  filename="Dark mode status color adjustment"
  language="css"
  code={`.dark {
  --success: 142 70% 45%;      /* +9% lightness */
  --warning: 45 93% 47%;       /* slight hue shift for warmth */
  --info: 217 91% 65%;         /* +5% lightness */
}`}
/>

## Usage Examples

Here is how to use color tokens in your components with Tailwind utility classes:

<CodeBlock
  filename="Color utility examples"
  language="tsx"
  code={`{/* Solid backgrounds */}
<div className="bg-primary text-primary-foreground">Primary button</div>
<div className="bg-destructive text-destructive-foreground">Delete</div>

{/* Opacity modifiers -- enabled by raw HSL storage */}
<div className="bg-success/10 text-success">Success banner</div>
<div className="bg-warning/5 border border-warning/20">Warning alert</div>
<div className="bg-primary/50">50% opacity primary</div>

{/* Semantic surfaces */}
<div className="bg-card text-card-foreground border border-border rounded-lg">
  Card content
</div>

{/* Text hierarchy */}
<h2 className="text-foreground">Heading</h2>
<p className="text-muted-foreground">Description text</p>

{/* Interactive states */}
<button className="bg-primary hover:bg-primary/90 focus-visible:ring-2 ring-ring">
  Action
</button>`}
/>

<DesignDecision title="Foreground Pairing Convention" type="tip">
  <p>
    Every surface token has a matching <code>-foreground</code> variant. When you use <code>bg-card</code>, always pair it with <code>text-card-foreground</code>. When you use <code>bg-primary</code>, always pair it with <code>text-primary-foreground</code>. This ensures sufficient contrast across all themes and modes without manual color checking.
  </p>
</DesignDecision>
